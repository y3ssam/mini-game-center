# UI/UX 및 그래픽 규격 (UI_SPEC)

- 버전: 1.0 / 2026-10-10
- 상태: 기존 화면 구조는 승인되지 않았으며 전면 재기획 중. 아래 구 레이아웃 설명은 구현 현황 기록용.
- 콘셉트: **모던 다크 UI + 2D 게임 그래픽**
- 탐색: **메뉴형 게임장** (게임장 / 알바 / 뽑기 / 도감)

## 1. 원칙

- 기능, 실제 데이터, 상태, 조작, 오류/검증에 필요한 UI 텍스트만 사용한다.
- 감성적 문구·홍보 문구·서비스 브랜드용 화면 타이틀을 만들지 않는다.
- 카드·박스·장식 배경을 과도하게 반복하지 않는다. 기본 게임 선택은 컴팩트한 목록 행을 사용한다.
- 메뉴 UI는 간결하게, 2D 그래픽·연출은 **미니게임/수집품 콘텐츠 내부**에 집중한다.
- 화면 이동, 게임 전환, 결과 오버레이로 다른 요소의 레이아웃이 밀리지 않도록 한다.
- 로딩, 비활성, 잔액 부족, 실패, 성공은 텍스트/아이콘과 함께 명확히 표현한다.

색상만으로 성공/실패를 구별하지 않는다. 텍스트/아이콘을 병행한다. 실제 구현 시 대비 검증을 수행한다.

## 3. 서체/간격/버튼

- 한국어 UI 기본: Pretendard (프로젝트 사용 가능 여부 확인), 폴백 Noto Sans KR 및 시스템 sans-serif.
- 기본 본문: 14px; 보조 정보 12~13px; 주요 화면 제목 22~24px.
- 기본 간격 단위: 8/12/16/24px; 모서리: 일반 8px, 다이얼로그 12px.
- 일반 버튼 시각적 높이 40px; **모바일 터치 타깃은 최소 44×44px**.
- 숫자 잔액과 배당은 가능하면 탭형 숫자(tabular numbers) 사용.
- 클릭 가능한 행은 전체 행이 터치 대상이며, 클릭 상태·포커스·비활성 상태를 구분한다.

## 4. 반응형 레이아웃

### 데스크톱 (폭 > 768px)
- 공통 상단 바 56px, 좌측 사이드 메뉴 192px, 나머지 메인 콘텐츠.
- 메인 콘텐츠 최대 폭 1100px; 과도한 카드형 대시보드 대신 목적 중심 화면.
- 상단에 보유 코인, 필요한 알바 수익 상태, 설정 노출.

### 모바일 (폭 ≤ 768px)
- 상단 바 52px, 하단 내비게이션 64px + safe-area-inset-bottom.
- 좌측 사이드 메뉴 제거. 게임장/알바/뽑기/도감 하단 탐색.
- 목록은 단일 열, 미니게임은 그래픽과 조작 버튼이 우선.
- 미니게임 진행 중 하단 글로벌 내비게이션 숨김/축소. **돌아가기**는 유지.
- 높이 제한이 있는 화면은 게임 콘텐츠/조작부가 시스템 안전 영역에 가려지지 않도록 조정.

### 공통 검증
- 최소 320px에서 가로 스크롤, 텍스트 잘림, 요소 겹침 금지.
- 320/360/390/768/1024/1440px 이상 주요 뷰포트 검증.
- 세로로 긴 모바일과 가로 모드에도 기본 조작 가능해야 함.
- 화면이 작으면 장식보다 게임 공간/조작을 우선 축소·재배치한다.

## 5. 내비게이션과 각 화면

### 게임장 목록
- 카테고리 필터: 전체/카드/주사위/기타 (실제 게임 구성에 따라 조정).
- 목록 행: 게임 아이콘, 게임명, 최소 베팅(해당 시), 실행/준비 중/잠김 상태.
- 게임 선택 시 메인 콘텐츠를 **게임 전용 뷰**로 교체; 새 창/새로고침 불필요.

### 게임 전용 뷰
- 상단: 돌아가기, 게임명, 잔액, 규칙 도움말.
- 본문: 게임 그래픽/현재 상태.
- 조작: 베팅 금액 선택 및 확인, 실제 플레이 액션, 결과, 재도전.
- 화면 상태: 대기 / 베팅 확인 / 진행 / 결과 / 재도전.
- 잔액 부족, 중복 클릭, 전환 중 탭을 안전하게 처리.
- 결과 애니메이션은 고정 영역 내에서 표시하고 사용자 입력을 예측 가능하게 관리.

### 알바
- 현재 근무, 누적 미수령 보수, 누적 상한, 수령 버튼.
- 직접 플레이형 알바 진입, 완료 보수, 재시도 대기 상태.
- 시간을 기다려야 하는 경우 남은 시간·급여 증가 조건 표시.

### 뽑기
- 굿즈 가챠만 제공한다. 시리즈 선택, 아이템 이미지, 개별 확률, 현재 잔액, 가격, 추첨 및 결과를 표시한다.

### 도감
- 굿즈 시리즈/희귀도 필터, 획득률, 이미지 그리드.
- 획득/미획득 표시, 상세 패널, 이름·희귀도·보유 수량.
- 미획득 아이템 노출 방식은 시리즈 기획에서 결정하며 스포일러 정책을 일관되게 유지한다.

### 설정
- 사운드, 애니메이션 감소/건너뛰기, 저장 상태, 데이터 백업/복원(추후).
- 설정 화면은 글로벌 메뉴 4개를 늘리지 않고 보조 진입으로 제공.

## 6. 팝업/오버레이

- fixed 또는 게임 영역 내 absolute 오버레이를 사용하여 레이아웃 흐름을 변경하지 않는다.
- PC 중앙 다이얼로그, 모바일은 너비·높이를 제한한 다이얼로그 또는 하단 시트.
- 닫기 버튼은 항상 시각적으로 존재하며, 키보드 Esc 처리/포커스 복귀를 지원한다.
- 열었을 때 배경 스크롤과 하위 입력을 적절히 차단한다.
- 중첩 다이얼로그는 가능한 피하고, 내용이 길면 패널 **내부만** 스크롤한다.

## 7. 2D 게임 그래픽

- UI 자체는 HTML/CSS/React를 우선하며, 복잡한 2D 그래픽 엔진은 필요한 콘텐츠가 확정된 경우에만 검토한다.
- 게임 루프의 프레임별 상태를 React 전역에 매 프레임 반영하지 않는다.
- 게임 내부의 애니메이션 오브젝트 위치와 게임머니/보상 정산은 분리.
- 2D 렌더 화면은 가용 공간에 비율을 유지하며 맞추고 조작 UI는 별도 배치.
- 효과음/애니메이션은 토글과 prefers-reduced-motion을 고려한다.

## 8. 에셋 정책

| 항목 | 기준 |
| --- | --- |
| 공통 UI 아이콘 | SVG, 24×24 기준 |
| 2D 게임 오브젝트 | WebP 또는 PNG, 오브젝트별 분리 |
| 투명 오브젝트 | 알파 채널 유지 |
| 배경 | WebP, 표시 비율과 모바일 구도 고려 |
| 가챠 굿즈 | 원본 이미지와 썸네일/도감 사용 크기 구별 |
| 단순 효과 | 가급적 CSS/SVG |
| 복잡한 애니메이션 | Phaser/Canvas |

공통 아이콘과 콘텐츠 이미지 자산을 구분하고, 임시/최종 에셋을 명확히 표기한다. **이모지나 임시 도형을 완성 에셋의 영구 대체물로 두지 않는다.**

## 9. 접근성·테스트 수용 기준

- 키보드 탭/포커스 표시, 보조 기술용 버튼 명칭, 도움말 및 입력 결과 안내.
- 게임 조작에 적합한 키보드 단축키, 터치 타깃 44px 이상.
- 성공/실패/잔액 부족은 색상 외 텍스트/아이콘 필수.
- 팝업 닫기, 스크롤, 게임 중 글로벌 내비게이션 가림 검증.
- 모든 핵심 화면을 PC와 모바일에서 테스트하고 Playwright에서 주요 흐름 회귀 테스트한다.


## 10. 대화형 UI 시안 (2026-10-10)

기존의 텍스트 행 중심 초기 화면에 대한 사용자 피드백을 반영하여, **게임장과 뽑기 콘텐츠 선택에는 실제 게임을 알아볼 수 있는 2D 이미지 타일**을 사용한다. 마케팅 문구·장식 카드·무의미한 서비스 브랜딩은 여전히 사용하지 않는다.

- 게임장: 가로 폭을 활용한 2열 2D 일러스트 게임 선택 타일, 모바일은 2열(320px에서 1열).
- 실제 플레이 UI 시안: 목록에서 전용 플레이 뷰로 전환하며, PC는 그래픽/조작패널을 분리하고 모바일은 수직으로 재배치한다.
- 모바일 미니게임/뽑기 체험 화면: 글로벌 하단 내비게이션을 숨기고 돌아가기 버튼을 유지한다.
- 알바: 현재 일자리와 보수 조건 중심 화면. 시간 경과·미수령 수익이 구현되기 전에는 가짜 수치를 표시하지 않는다.
- 굿즈 가챠: 시리즈 전환 및 희귀도 확률 예시. 아이템 개별 확률과 추첨은 미구현.
- 도감: 필터와 공통 수집 정보 배치 시안, 실제 보유 데이터가 없는 상태는 명확히 표시.
- 임시 일러스트는 React SVG 벡터 컴포넌트로 제작한다. 실제 콘텐츠 에셋/게임 엔진 연출과 구분한다.
- 모든 UI 체험은 실제 코인 잔액에 영향을 주지 않으며, 정식 게임 로직과 연동되기 전까지 "UI 체험" 및 "준비 중" 레이블을 유지한다.

## 11. 최신 범위 및 디자인 재검토

- 인형뽑기 기능과 인형 수집은 폐기한다. 뽑기 메뉴에는 굿즈 가챠만 포함한다.
- 이 문서의 PC 사이드바·모바일 하단 내비게이션·게임 선택 타일은 과거 시안의 기록이며 **새 설계의 확정 요구사항이 아니다**.
- 사용자 승인을 받기 전에는 기존 배포된 UI를 최종 디자인으로 간주하지 않는다.
